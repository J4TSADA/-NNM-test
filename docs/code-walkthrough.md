# เดินทางไปกับไฟล์ลงเวลา 1 ไฟล์

เอกสารนี้เล่าว่าเกิดอะไรขึ้นบ้าง ตั้งแต่ผู้จัดการกดอัปโหลดไฟล์จนเห็นตารางสรุป อ่านจบแล้วควรแก้โค้ดต่อได้เอง

## 1. ผู้จัดการเลือกไฟล์ (`src/main.ts`)

หน้าเว็บมีแค่ช่องเลือกไฟล์กับปุ่ม "ลองด้วยไฟล์ตัวอย่าง" พอเลือกไฟล์ เบราว์เซอร์อ่านเนื้อไฟล์เป็นข้อความด้วย `file.text()` แล้วส่งต่อให้ `showResult`

ไฟล์ไม่ถูกส่งออกไปที่ไหนเลย ทุกอย่างคำนวณในเบราว์เซอร์ของผู้จัดการเอง ระบบจึงไม่มีเซิร์ฟเวอร์ ไม่มีฐานข้อมูล และไม่มี secret

`showResult` ทำงานแค่ 2 ขั้น คืออ่าน CSV แล้วสรุป ถ้าขั้นไหนพังจะจับ error มาแสดงเป็นข้อความสีแดง หน้าเว็บไม่ค้าง

## 2. แปลงข้อความเป็นรายการลงเวลา (`src/csv.ts`)

`parseAttendanceCsv` รับข้อความทั้งไฟล์แล้วคืนรายการ `AttendanceRecord` (หน้าตาดูใน `src/types.ts`)

ระหว่างทางมันจัดการ 2 เรื่องที่เจอบ่อยกับไฟล์จาก Excel

- ตัด BOM (อักขระที่มองไม่เห็นต้นไฟล์) ทิ้ง
- รองรับทั้งการขึ้นบรรทัดแบบ `\n` และ `\r\n`

มันอ่านตำแหน่งคอลัมน์จากหัวตาราง คอลัมน์จะเรียงสลับกันก็ได้ ถ้าขาดคอลัมน์ไหนจะโยน error ภาษาไทยบอกชื่อคอลัมน์ที่ขาด

## 3. คำนวณสรุป (`src/summary.ts`)

นี่คือหัวใจของระบบ `summarizeWeek` ทำ 3 อย่าง

1. **จับกลุ่มตามคน:** ใช้ `Map` โดยมี `employeeId` เป็นกุญแจ ลำดับคนในตารางจึงเรียงตามที่ปรากฏในไฟล์
2. **สรุปรายคน (`summarizeEmployee`):** แปลงเวลาเป็นนาทีด้วย `toMinutes` แล้วคำนวณ
   - วันทำงาน: นับวันที่ไม่ซ้ำด้วย `Set`
   - ชั่วโมงรวม: (ออก − เข้า) ของทุกวันรวมกัน
   - มาสาย: นับวันที่เวลาเข้า **มากกว่า** `WORK_START` ดังนั้น 08:00 พอดีไม่สาย
   - OT: ของแต่ละวันคิดเฉพาะส่วนที่เกิน `STANDARD_HOURS_PER_DAY` แล้วรวมกัน
3. **เขียนภาพรวม 3 บรรทัด (`buildOverview`):** ชั่วโมงรวมทั้งทีม คนที่สายบ่อยสุด และคนที่ทำ OT มากสุด ถ้าทั้งสัปดาห์ไม่มีใครสายหรือไม่มี OT ก็จะเขียนบอกตรง ๆ

ตัวเลขทุกตัวปัดเป็นทศนิยม 2 ตำแหน่งด้วย `round2` กันปัญหาเลขทศนิยมของ JavaScript เช่น 0.1 + 0.2

## 4. กติกาอยู่ที่ไหน (`src/rules.ts`)

เวลาเข้างานและชั่วโมงมาตรฐานต่อวันอยู่ในไฟล์นี้ที่เดียว ถ้าตลาดเปลี่ยนเวลาเข้างานเป็น 07:30 ก็แก้บรรทัดเดียว แล้วรัน `npm test` ดูว่าเทสต์ไหนต้องปรับตาม

## 5. แสดงผล (กลับไปที่ `src/main.ts`)

`renderSummary` สร้างตารางด้วย `textContent` ทั้งหมด ไม่ใช้ `innerHTML` ถ้าในไฟล์มีชื่อแปลก ๆ ที่เป็นโค้ด HTML ก็จะแสดงเป็นตัวอักษรธรรมดา ไม่ถูกรันเป็นโค้ด ช่อง "มาสาย" ที่มากกว่า 0 จะเป็นสีส้มให้ผู้จัดการเห็นง่าย

## 6. อะไรกันพังไว้บ้าง

- **เทสต์ (`src/*.test.ts`):** ใช้ `fixtures/sample-week.csv` และค่าที่คำนวณมือไว้ ชื่อเทสต์อ้าง AC ใน `intent.md`
- **ก่อน commit:** ESLint และ Prettier รันอัตโนมัติ ข้อความ commit ผิดรูปแบบจะ commit ไม่ได้
- **CI:** ทุก PR ต้องผ่าน lint, format, typecheck, test และ build
