# เดินทางไปกับไฟล์ลงเวลา 1 ไฟล์

เอกสารนี้เล่าว่าเกิดอะไรขึ้นบ้าง ตั้งแต่ผู้จัดการวางไฟล์ลงในหน้าเว็บจนเห็นตารางสรุป อ่านจบแล้วควรแก้โค้ดต่อได้เอง

## 1. ผู้จัดการวางไฟล์ (`src/main.ts`)

หน้าแรกมีกรอบเส้นประให้ลากไฟล์มาวาง หรือคลิกเพื่อเลือกไฟล์ ใต้กรอบบอกไว้ว่าไฟล์ต้องมีคอลัมน์อะไรบ้าง และมีปุ่ม "ลองด้วยไฟล์ตัวอย่าง" ที่โหลด `public/sample-week.csv` มาใช้

ไม่ว่าไฟล์จะมาทางไหน สุดท้ายจะไปจบที่ฟังก์ชัน `show` ซึ่งทำ 3 ขั้น

1. อ่านไฟล์ด้วย `parseAttendanceCsv`
2. สรุปด้วย `summarizeWeek`
3. วาดผลลัพธ์ คือภาพรวม กล่องคำเตือน (ถ้ามี) และตารางรายคน

ถ้าขั้นไหนโยน error ออกมา `show` จะจับไว้แล้วแสดงกล่องสีแดงพร้อมวิธีแก้ หน้าเว็บไม่ค้าง

ไฟล์ไม่ถูกส่งออกไปที่ไหนเลย ทุกอย่างคำนวณในเบราว์เซอร์ของผู้จัดการเอง ระบบจึงไม่มีเซิร์ฟเวอร์ ไม่มีฐานข้อมูล และไม่มี secret

## 2. แปลงข้อความเป็นรายการลงเวลา (`src/csv.ts`)

ไฟล์ที่มาจาก Excel ของแต่ละที่หน้าตาไม่เหมือนกัน `parseAttendanceCsv` เลยต้องยืดหยุ่น มันคืนค่าออกมา 2 อย่าง คือ `records` (แถวที่ใช้ได้) และ `warnings` (แถวที่อ่านไม่ออก)

- **หัวคอลัมน์:** `COLUMN_ALIASES` เก็บชื่อที่ยอมรับได้ของแต่ละคอลัมน์ ทั้งไทยและอังกฤษ ถ้าไม่มีคอลัมน์รหัส จะใช้ชื่อคนเป็นรหัสแทน ถ้าขาดคอลัมน์จำเป็น จะโยน error บอกชื่อคอลัมน์ภาษาไทย
- **แยกช่อง:** `splitCsvLine` อ่านทีละตัวอักษร ช่องที่ครอบด้วย `"..."` จึงมีคอมมาข้างในได้ เช่น `"ใจดี, สมใจ"`
- **วันที่:** `normalizeDate` รับทั้ง `2026-11-23` และ `23/11/2569` ถ้าปีเกิน 2400 ถือว่าเป็น พ.ศ. แล้วลบ 543 วันที่ที่ไม่มีจริง เช่น 31/02 จะได้ค่าว่าง แถวนั้นจะถูกย้ายไปอยู่ใน `warnings`
- **เวลา:** `normalizeTime` รับ `8:05`, `08.05` และ `08:05:00` แล้วแปลงเป็น `08:05` ทั้งหมด เวลาที่อ่านไม่ออกจะกลายเป็นค่าว่าง
- **ไฟล์จาก Excel:** ตัด BOM (อักขระที่มองไม่เห็นต้นไฟล์) ทิ้ง และรองรับการขึ้นบรรทัดทั้ง `\n` และ `\r\n`

## 3. คำนวณสรุป (`src/summary.ts`)

นี่คือหัวใจของระบบ `summarizeWeek` จับกลุ่มแถวตามคนด้วย `groupBy` แล้วส่งให้ `summarizeEmployee` ทีละคน ข้างในจับกลุ่มซ้ำอีกชั้นตามวัน เพราะกติกาส่วนใหญ่คิดเป็นรายวัน

ของแต่ละวัน

- **วันทำงาน:** นับถ้ามีเวลาเข้าหรือเวลาออกอย่างน้อย 1 ช่อง แถวที่ว่างทั้งสองช่องถือว่าไม่ได้มา
- **ชั่วโมง:** `workedHours` คิด (ออก − เข้า) ของแต่ละแถว ถ้าขาดเวลาใดเวลาหนึ่ง หรือเวลาออกมาก่อนเวลาเข้า จะได้ 0 ชั่วโมงและเพิ่มคำเตือน
- **OT:** รวมชั่วโมงของทั้งวันก่อน แล้วคิดเฉพาะส่วนที่เกิน `STANDARD_HOURS_PER_DAY` วันที่ลงเวลา 2 รอบ เช่นเช้ากับบ่าย จึงคิด OT ถูกต้อง
- **มาสาย:** ดูเวลาเข้ารอบแรกของวัน ถ้า **มากกว่า** `WORK_START` นับว่าสาย 1 ครั้ง แถวที่เวลาออกมาก่อนเวลาเข้าไม่ถูกนำมาคิด เพราะข้อมูลแถวนั้นเชื่อไม่ได้

หลังสรุปครบทุกคน `summarizeWeek` เช็กอีกอย่างคือ ถ้าวันแรกกับวันสุดท้ายในไฟล์ห่างกันเกิน 7 วัน จะเพิ่มคำเตือนว่าไฟล์อาจไม่ใช่ข้อมูล 1 สัปดาห์

สุดท้าย `buildOverview` เขียนภาพรวม 3 บรรทัด คือชั่วโมงรวมทั้งทีม คนที่สายบ่อยสุด และคนที่ทำ OT มากสุด วันที่แปลงเป็นแบบไทยด้วย `toThaiDate` เช่น `23 พ.ย. 2569` ตัวเลขทุกตัวปัดเป็นทศนิยม 2 ตำแหน่งด้วย `round2` กันปัญหาเลขทศนิยมของ JavaScript

## 4. กติกาอยู่ที่ไหน (`src/rules.ts`)

เวลาเข้างานและชั่วโมงมาตรฐานต่อวันอยู่ในไฟล์นี้ที่เดียว ถ้าตลาดเปลี่ยนเวลาเข้างานเป็น 07:30 ก็แก้บรรทัดเดียว แล้วรัน `npm test` ดูว่าเทสต์ไหนต้องปรับตาม

## 5. แสดงผล (กลับไปที่ `src/main.ts`)

ทุกอย่างบนหน้าจอสร้างด้วย `textContent` ไม่ใช้ `innerHTML` ถ้าในไฟล์มีชื่อแปลก ๆ ที่เป็นโค้ด HTML ก็จะแสดงเป็นตัวอักษรธรรมดา ไม่ถูกรันเป็นโค้ด

- **ภาพรวม:** 3 บรรทัด มีแถบสีด้านซ้ายแยกความหมาย เขียวคือชั่วโมง แดงคือมาสาย เหลืองคือ OT
- **กล่องคำเตือนสีเหลือง:** รวมคำเตือนจากทั้งขั้นอ่านไฟล์และขั้นสรุป บอกชื่อ วันที่ และเหตุผล
- **ตาราง:** ช่องมาสายและ OT ที่มากกว่า 0 เป็นป้ายสี ค่า 0 เป็นสีจาง บนมือถือตารางจะบีบให้เห็นครบทุกคอลัมน์

## 6. อะไรกันพังไว้บ้าง

- **เทสต์ (`src/*.test.ts`):** ใช้ `fixtures/sample-week.csv` และค่าที่คำนวณมือไว้ ชื่อเทสต์อ้าง AC ใน `intent.md`
- **ก่อน commit:** ESLint และ Prettier รันอัตโนมัติ ข้อความ commit ผิดรูปแบบจะ commit ไม่ได้
- **CI:** ทุก PR ต้องผ่าน lint, format, typecheck, test และ build
